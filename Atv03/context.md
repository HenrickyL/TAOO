Contexto
Nesta atividade, você receberá a implementação de um pequeno sistema de pedidos. O programa está funcionalmente correto, porém foi desenvolvido sem preocupação adequada com a qualidade do código e com boas práticas de programação.

São disponibilizadas duas implementações equivalentes:

uma em Python;

uma em Java.

Você deverá escolher uma das duas linguagens para realizar a atividade.

Você pode utilizar o código fornecido como ponto de partida ou, caso considere mais conveniente, implementar sua própria versão do programa na linguagem (porém deve ser implementada em Python ou Java).

Independentemente da estratégia adotada, o comportamento especificado do sistema deverá ser preservado. Os códigos estão anexados em arquivos na página da disciplina. Além disso, a descrição funcional do código está na atividade do VPL.

Sua tarefa
Analise a implementação disponibilizada e refatore o programa procurando melhorar sua qualidade interna.

Considere, entre outros aspectos discutidos durante a disciplina:

escolha de nomes significativos;

encapsulamento;

responsabilidades das classes e métodos;

coesão;

acoplamento;

duplicação;

organização e legibilidade;

uso adequado de abstrações;

separação entre regras de negócio, entrada e saída;

oportunidades de utilização de composição, delegação, herança ou polimorfismo, quando fizerem sentido.

Você não é obrigado a utilizar todas essas técnicas. Cabe a você decidir quais alterações melhoram efetivamente o projeto.

Também não existe uma única estrutura de classes considerada correta.

O principal requisito é que a estrutura interna seja melhorada sem alterar o comportamento especificado do sistema.

Entrega
1. Código-fonte - VPL
Envie a versão final refatorada do programa.

Para Python, o ponto de entrada deverá ser:

sistema.py
Para Java, deverá existir a classe principal:

Sistema
no arquivo:

Sistema.java
Outros arquivos e classes auxiliares poderão ser criados, caso sejam necessários.

Envie apenas uma das versões, Python ou Java.

O VPL executará diferentes pedidos e verificará se o comportamento da implementação foi preservado.

2. Relatório - Moodle
Entregue também um relatório em PDF contendo:

os principais problemas de qualidade identificados no código original;

as principais alterações realizadas;

a justificativa para essas alterações;

exemplos de trechos antes/depois, quando forem úteis para a explicação;

um diagrama UML representando a estrutura final da solução.

Não é necessário descrever cada linha modificada.

O relatório deve se concentrar principalmente nas decisões de projeto e refatoração.

Importante
Os testes automáticos verificam apenas o comportamento do sistema.Passar em todos os testes do VPL não significa, por si só, que o código possui boa qualidade. A estrutura da solução e as decisões de refatoração serão avaliadas separadamente.
